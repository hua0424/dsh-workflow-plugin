# 右侧栏工作流监控：展示优化与执行记录

状态：设计已确认，待另行授权实施。用户通过三轮澄清确认下述展示与交互规则；设计确认不代表开发、建票或部署授权。本轮仅修改设计文档与术语，未完成真实 GUI 视觉验收。

## 1. 目标与边界

改善工作流监控的视觉层级与文字可读性；在流程图下显眼展示当前节点、角色、模型；允许仅用于查看的临时节点布局；提供可追溯的执行记录。

沿用 [ADR-0005](../adr/0005-run-monitor-sidebar-tab.md) 的右侧栏、运行冻结快照与只读监控边界，不增加 resume/reset/换模控制。允许查看位置变化，不等于允许编辑工作流。术语沿用 [CONTEXT.md](../../CONTEXT.md)，不另建重复 glossary。

新增模型事实采集属于未来实施范围，但监控读取仍只读，不通过监控请求触发派发或改变状态机推进。保留现有刷新、Run 选择和子流程导航的职责，不借此次改版扩大为流程编辑器。

## 2. 信息架构与视觉

自上而下：

1. 工作流监控标题、Run 选择/状态与刷新入口。
2. 运行图及定位当前、适应视图、恢复布局操作。
3. 独立的当前执行卡：节点名称为显眼主标题，角色、模型和状态不需展开即可查看。
4. 执行记录表：一条记录一行，横向滚动。
5. 所选节点详情、运行信息、启动 Prompt 等辅助内容。

```text
工作流监控                                刷新
流程名称 / Run                            运行状态

运行图           定位当前 / 适应视图 / 恢复布局

当前节点：实现需求                         等待判定
Actor  开发者       模型 B · 备选          已提交结果
Judge  独立检查者   模型 C · 首选          待判定

执行记录
节点 / 所属流程 | 状态 | 进入时间 | 提交结果时间 | 提交判定时间 | Actor 模型 | Judge 模型
                  ← 横向滚动，节点列固定 →

所选节点详情 / 运行信息 / 启动 Prompt
```

示意中的模型名与状态仅用于说明结构，不代表真实运行数据。

视觉采用与宿主深浅主题协调的高对比、简洁分区。节点名、角色、模型、正文使用主题正文色；灰色仅用于仍可读的辅助信息。使用字号、字重、留白建立层级，减少细碎边框。状态采用文字配合颜色，不仅依赖颜色。流程图默认高度适中，不把图下的当前执行信息挤出主要查看区域。

具体像素、列宽与颜色 token 留待实现时结合现有主题和真实侧栏宽度校准；这不是新增功能决策，也不能仅凭源码断言已满足视觉可读性。

## 3. 当前执行与所选详情

当前执行与所选节点详情分离：查看历史或点击其他节点不能改变当前执行卡所表示的真实位置。历史详情绑定具体执行记录，而非只绑定同名节点。

当前执行卡同时列出 Actor 和 Judge，展示角色、实际派发模型、来源和各自状态；不是在同一行静默切换执行者。

- 未派发：明确标注，不提前将配置模型展示为已使用模型。
- 已安排但无法确认派发：中性提示，不能声称正在执行。
- 等待 Actor 收口：明确标注；不能只凭 checking 就显示 Judge 正在运行。
- 已提交结果或判定：分别标注对应事实，不等同于 Host Turn 已结束。
- BLOCK：突出显示阻塞状态与原因摘要，不隐藏原业务阶段。
- Program / Child：展示相应节点类型，不虚构 Actor/Judge 模型。
- Run 完成或终止：卡片展示终态，不再声称存在当前正在执行的节点；终止位置与末次记录可用于查看，但不冒充活跃执行。

Manager 实际模型没有可靠来源时明确标注；不能用 Run 启动时冻结的默认路由冒充当前实用模型。

## 4. 执行记录表

### 4.1 列与范围

使用横向滚动表格，不采用多行卡片；一条 Node Execution 占一条主行。节点列固定，所属流程靠左，滚动到模型和时间列时仍能辨认记录身份。

字段：节点名称、所属流程/路径、运行情况、进入时间、提交结果时间、提交判定时间、Actor 模型、Judge 模型。显示名称沿用可用节点标识，不要求新增配置字段。

模型可显示简短值，但必须有查看完整 provider/modelId 的方式，不能只保留截断文本。时间默认可读到秒，跨日期明确日期；进入时间表示进入工作单，不等于模型开始运行。时间格式使用一致时区，不以时间显示值决定执行先后。

- 覆盖选中 Run 的根流程及全部已进入的子流程，不混入其他 Run。
- 按进入顺序最新在上，旧记录更新不改变其位置。
- Run 全局 visit 是进入顺序，不是单节点重跑次数。
- 当前活跃节点由上方当前执行卡承载，不重复占据主表行。
- 已进入但等待子流程返回的父节点仍在表中，状态为等待子流程；执行记录不等于已完成记录。
- 终态不再有活跃当前节点，末次记录也应在表中可查。终止、未完成、阻塞不能统一画成成功。

### 4.2 多轮汇总与下钻

沿边重新进入同一节点（包括自环、回边）新增记录；同一进入内部的 REJECT、补充、恢复、重试或换模不新增主表行。

主行展示最新一轮 Actor/Judge 派发的对应事实；两侧分别关联自己的派发身份，不假设 Actor 与 Judge 次数一一对应：

- Actor 模型与提交结果时间必须来自同一次 Actor 派发。
- Judge 模型与提交判定时间必须来自同一次 Judge 派发，并保留它对应的 claim 关联。
- 新一轮尚未提交时显示待提交；不能把上一轮提交时间拼到新模型旁边。
- 新 Actor 结果尚未产生对应 Judge 时，旧 Judge 判定不能充当新结果的判定。
- 主行标记多轮执行，展开显示各轮派发、模型、提交、判定和换模情况；旧轮次留在明细中。
- 比如 Actor 从 A 切到 B 后主行显示 B，A 保留于此前轮次；无可靠实派证据时，不因已配置 B 就声称 B 已运行。

明细可在主行下展开，主记录本身仍保持一条一行；点击记录查看详情不影响当前执行卡。

## 5. 时间、模型与缺失值合同

### 5.1 时间

用户已决定不展示 Actor/Judge 实际执行结束时间，也不为此新增结束时间采集。

- 提交结果时间：对应 Actor 结果提交被记录的时间。
- 提交判定时间：对应 Judge 判定提交被记录的时间，包括 ACCEPT、REJECT、NEED_CONTEXT 等实际判定。
- 两者都不等于 Turn 结束、安全收口或节点退出时间，不用 exitedAt、下一条事件时间、Run.updatedAt 代替。

### 5.2 实际模型与来源

展示该次实际派发使用的模型，不显示当前配置来代替历史。为今后的执行补充必要的结构化模型快照、来源及派发关联，读取时区分已安排和已实际派发；不新增完整遥测系统。

来源按运行事实区分首选、备选、人工指定；人工指定即使恰好与首选/备用同值，仍标人工指定，不通过比较 modelId 推断。历史来源无法确认时明确标注来源未知，不以当前阶段回填。

规划涉及现有 Runtime/Host 派发边界的最小必要记录补充；具体兼容存储方案需实施前核实，但不得改变既有授权、派发身份与安全收口合同。复用现有 Judge 快照和事件能力，不另造一套执行引擎。

### 5.3 缺失值

- 待提交：有当前轮次且尚未发生对应提交。
- 未派发 / 已安排但派发未确认：按证据区分。
- 未记录：发生过历史执行但该字段无可靠记录。
- 不适用：该节点类型没有对应 Actor/Judge 数据。
- 来源未知：模型值可确认但首选/备选/人工来源不可确认。

旧数据有可靠结构化记录就展示；无法还原的不反向猜补，不从当前配置或日志文本推算历史模型，不将缺失当作持续执行或零耗时。Manager 无可靠实际模型来源同样遵循此规则。

## 6. 临时布局

允许空白处平移、缩放、单节点临时拖动，连线随节点位置变化；不允许增删节点、修改节点内容、连接关系或手动编辑连线路径，不提供保存入口。

临时状态仅在当前页面内按 Run/流程隔离：轮询、收起再打开侧栏、切换流程或 Run 后返回均保留；刷新整个页面后清除。不写布局文件或浏览器持久存储。

恢复布局只重置正在查看的流程；定位当前只改变查看位置，不撤销临时节点调整。保持配置编辑器原有编辑能力，不因共享画布改造而影响编辑器。
