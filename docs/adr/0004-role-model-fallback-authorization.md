# 显式授权的单备用路由与有限恢复链

状态：已实施（#235 / #236 / #237；真实 Host 兼容证据在验收记录中单独核对）。

旧设计排除模型 fallback；现在仅对显式配置 fallbackModel 的 Role Actor / Judge 引入自动故障切换，不包含 Manager 主会话。原始链为 A → B → BLOCK，人工指定 C 后授权新一轮 C → A → B → BLOCK：人工路由不是永久停用自动策略，但每轮必须有限，node_resume 和进程重启均不得刷新预算。已配置备用时直接采用这条链而不叠加 Judge 同模型 fresh retry；未配置备用保留现有行为。选择这一边界是为了在用户预先授权下减少临时不可达导致的中断，同时避免任意选模、反复回切和多层重试放大。

「新一轮」只由**成功的人工设置**触发，普通角色与 Judge 同规则（#237）：C 与 A/B 相同也照常授权，但不会把「值没变」当成 no-op 静默吞掉轮次；只有当前已处于人工阶段（stage=manual、预算 0）且三元件相同时，重复设置才回「无需变更」。A/B 始终取自 Run 冻结快照，人工 C 与运行中改 YAML 都不改写它们；B 用尽后再次人工设置 C 能把阶段从 fallback 拉回人工轮，之后仍按 C → A → B → BLOCK 重走。

确认模型请求终止失败与确认可安全续作是两个独立条件。只对明确的 5xx、429、网络故障、请求超时考虑切换；不因业务返工、认证/额度/参数/上下文错误或未知故障换模。保留已发生事实和已接受提交，旧执行收口且材料充分后检查现场续作，不重放整任务；不确定外部副作用时 BLOCK。第一版不取消宿主无限重试、不加 watchdog，因此无法保证此配置下及时切换。放弃“所有异常都不中断”的目标，是为了不把模型可用性恢复误当成重复外部写操作的授权。

在途派发的归因（#243）：人工设置只授权下一次派发，不替换正在进行的派发；该派发若随后以合格故障终局，切换按“实际运行的路由”归因——通知、trace 与恢复材料的来源写中性标注「人工路由未实派」，不把从未运行过的 C 写成失败来源。授权边界与轮次结构不变（仍是离开人工阶段回 A、消耗本轮第 1 次切换），本补充只修正归因的可观察性，不放宽或收紧任何授权条件。

详细配置、持久性、GUI 范围和验收场景见 [Role / Judge 单备用模型故障切换](../specs/role-model-fallback.md)。本 ADR 只扩展模型故障恢复范围，不修改现有静态路由校验规则或业务验收合同，也不授权实施、真实 Run 或部署。
