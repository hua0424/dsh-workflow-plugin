# 工作流材料入口

本文件只规定跨工作流适用的材料使用原则，不指定角色、节点、报告数量、仓库拓扑或运行目录布局。具体要求由当前工作流显式引用的合同定义；没有某个角色、节点或文件名本身不是阻塞理由。

## 先定位当前运行

从派发上下文或 handoff 获取运行入口的绝对路径，核对 workspace、仓库标识/路径/远端、当前对象及适用合同路径与版本。不依赖历史会话记忆，也不按当前 cwd 猜测目标仓库或材料位置；多仓工作流须明确本次操作归属的仓库。

运行入口应索引当前工作流声明的必需材料。只核验本节点实际需要的材料，按需读取详细记录，不预建其他工作流的目录和空报告。只有缺少本节点必需身份、合同或证据，影响执行/核验时，才报告确切缺口并按该流程处理。

## 共同记录原则

- 证据注明仓库、对象、相关修订、查询/验证时间与结果；不把本地记录当成实时远端状态。有副作用的操作前重新核验会变化的关键事实。
- 按当前合同约定的归属编辑材料，保留其他执行者内容及历史结论；职责未定义或冲突时先解决具体冲突，不自行指定某个不存在的角色负责。
- handoff 简短传递运行入口、当前对象、结果、证据入口与后续约束，使用能明确定位的路径；遵守当前工具参数及长度限制。
- 不记录凭据或未脱敏敏感日志。不要擅自清理、迁移运行产物或改写用户内容。
- ignored 本地材料不会随 push、clone 或 worktree 自动共享。跨环境执行时确认当前节点所需材料可访问；需要远端留痕的结论按当前合同同步必要摘要，不能只贴接收方无法访问的本地路径。

## 合同适用与版本

由当前工作流明确采用哪些合同及版本。文档不会因 YAML 定义冻结而自动冻结；需要稳定合同的流程应在初始化保存适用内容副本或可重现的版本，并在运行入口引用。已有运行按其实际采用的合同执行，不能因切换工作流或更新本目录而自动迁移；不确定时核对旧定义和材料后再处理。
