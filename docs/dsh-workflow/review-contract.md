# 审查证据格式

本文件仅在当前工作流显式引用时适用，描述审查与处置证据，不强制特定角色、节点、两个文件或某种 PR 层级。引用方声明写入责任、存放方式、必需证据、结论对应的路由与远端同步范围。可合为一个文档，也可分开存放；`milestone-delivery` 的双文件要求见其专属合同，不自动适用于其他工作流。

## 审查证据

至少记录：

- 仓库身份、对象/PR URL、轮次、observedAt、baseBranch/headBranch、完整 baseSha/headSha、mergeBaseSha（区分 PR base tip 与 diff 起点）；非 PR 对象提供等价的固定范围标识。
- 范围与方法：验收入口、精确 diff 或审查对象、检查过的证据、未核实项。
- 发现列表：稳定编号如 r001-F1、位置/证据、影响、建议；没有发现明确写“无”。
- 建议结论、上轮必修项的复核状态。流程内结论不冒称已提交正式 GitHub approval。

默认审查固定修订的完整范围。仅当 base 未变、head 是上轮 head 的后继且旧发现全部可追踪时，允许增量审查，仍须复核旧必修项。分支/base 漂移、范围改变或材料不足时重新确定完整范围，不能继承旧批准。

引用其他对象的旧证据时说明仓库、对象、修订、覆盖范围与适用依据，补齐当前对象的差异和验收。旧证据不自动成为当前修订的批准。

## 处置与批准证据

记录对应审查入口与同一仓库/对象/修订；每项发现的核实结论、处置（本次修复/延期/不成立）和理由；剩余必修清单；批准或返工结论。修复复杂不是延期阻断问题的理由；范围/授权争议按当前工作流交给有权决策者。

通过才记录 approvedBase/approvedHead 或等价的固定批准范围；返工不保留有效批准。延期记录理由、影响、必要授权及后续入口，不能把“已登记”当成“已修复”。

## 轮次与更新

- 轮次按对象分别递增，先读取上一轮，再固定本轮，不能把刚写的本轮当作上一轮。
- 相同对象、修订且任务未改变的重入可复用原轮次；补充/纠错注明时间和原因，保留旧结论。
- 不同修订（head 或 base 变化）开新轮次；按引用方的布局存放，不要求其他流程创建 rNNN-review/decision 文件。
- handoff 只摘要和引用；需要远端同步时保留远端可读的关键结论和修订信息，不只有本地路径。
- 变更实现、head 或批准 base 后，原批准失效；合并前发现漂移时按当前流程阻塞并安排新修订审查，补充身份或查询证据不能代替新修订的专业评审。
