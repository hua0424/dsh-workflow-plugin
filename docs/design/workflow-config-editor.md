# 工作流图形配置编辑器（设计讨论中）

## 已确认方向

- 目标是生成和修改当前 `agent-workflow/v3` YAML 配置，表单与画布共同覆盖当前 schema 支持的字段，包括角色、模型、persona、主流程、子流程和节点配置，不仅编辑节点关系。
- 使用 React Flow 提供节点拖动、连接端口、连线、选择和视口交互；不自研 SVG 编辑器，不选择 X6。
- 不实现拓扑自动布局，不引入 Dagre、ELK。布局保存在 YAML 同级的独立配置文件，无布局文件时简单摆放；通过浏览器授权目录自动读取同级布局文件。
- 公共配置、角色及节点详细属性使用普通表单；画布表达流程节点和结果路由。不将角色、模型等非执行步骤画成流程节点。
- 优先复用本项目已有 `yaml`、schema、parser、validator 及 Program 元数据；最终校验复用服务端合同，不复制一套浏览器校验规则。
- 配置草稿作为业务数据来源，图形为其编辑投影；画布坐标与业务 YAML 分离，不向严格 v3 schema 添加 UI 字段。
- 参考 dsh-knj-workflow 的交互思路，不移植其 JSON 工作流模型、自研 SVG 或 DOM 注入接入方式。宿主客户端加载及 React 兼容性仍需验证。

## 已确认：自环与多节点回路

- 直接自环指节点出口指向自身，即 `A → A`；编辑器禁止创建此类连接。
- 这是编辑器限制，不修改现有 YAML schema、validator 或运行时允许直接自环的合同。
- 加载含直接自环的 YAML 时明确提示并阻止进入图形编辑，需先修正后再进入；不静默删除连线或改变结果去向。具体修正入口随文件加载方案确定。
- 继续支持 `A → B → A` 等多节点回路（例如开发、审查、返工），不将流程视为 DAG。
- 节点直接自环与子流程递归调用是不同概念，不改变既有子流程调用限制。

以上边界已由用户确认。

## 已确认：入口、文件操作和输出格式

- 嵌入 DSH Web 的独立配置页面，复用宿主环境，不另起服务；具体可用扩展入口及打包兼容性仍需核实。
- 文件入口改为“打开目录”：通过浏览器 File System Access API 授权，列出目录中的 YAML，选择 YAML 后自动加载固定名称的同级布局文件，不提供布局文件选择器。此决定取代此前“仅普通文件导入/下载、不覆盖原文件”的方案。
- 保存由用户显式触发，将 YAML 与布局写入明确授权的目录；点击保存即直接覆盖目标文件，不检查外部修改、不做冲突合并、不额外弹出覆盖确认；此行为由用户明确选择。不自动保存未完成草稿，不增加服务端任意路径读写接口，不隐式定位真实 catalog。浏览器访问的是浏览器所在机器的目录，而非远程 DSH 服务器目录。
- 优先支持具有目录访问 API 的 Chrome/Edge；实际 DSH 页面上的安全上下文、API 可用性与授权需验证。不支持或拒绝授权时明确提示，不悄悄改为手选布局文件。
- 导出保证支持当前配置字段且保持业务含义，统一格式输出，不保证原注释、字段顺序或排版；打开时及保存操作说明中明确提示格式规范化与直接覆盖行为，不另设覆盖确认弹窗。
- YAML 规范化输出不意味着可以静默忽略未知字段或改写不支持的配置；此类问题应明确诊断。

## 已确认：编辑行为

- 保存布局：在 YAML 同级保存独立布局配置文件；加载时无布局文件则简单摆放。不持久化未完成的配置草稿。
- 导入时拒绝不合法配置并展示具体错误；直接自环按编辑器限制拒绝进入图形编辑。用户在外部修正 YAML 后重新导入。
- 编辑过程中允许配置暂时不完整，导出 YAML 必须通过完整配置校验及编辑器限制检查。
- 提供只读 YAML 预览，不提供源码编辑；未通过校验的预览明确标记为草稿。
- 提供有上限的页面内撤销/重做，覆盖表单修改、节点和连线的增删及移动，不跨刷新恢复。

## 已确认：布局文件规则

- `review.yaml` 对应同目录 `review.layout.json`，按固定规则自动加载，不提供单独选择或关联布局文件的操作。
- 布局按主流程/子流程 ID 与节点 ID 记录坐标，不重复保存业务配置或连线。
- 缺少坐标的节点简单补位，多余节点记录忽略；布局损坏时提示并回退简单摆放，不阻止合法 YAML 编辑。
- 自动读取同级文件通过用户已确认的浏览器目录授权完成，不改为服务端任意路径读写。

## 已确认：保存和离开保护

- 不检查外部文件变化；显式保存直接覆盖目标，可能覆盖用户在其他编辑器中的并行修改。此风险已作为设计取舍接受，不做自动合并。
- 仅位置等布局变化时只写布局文件，不重写 YAML。配置变化时通过完整校验后保存 YAML 及布局；直接覆盖不意味着跳过配置校验。
- 两个文件不能保证整体原子写入。部分失败必须分别报告 YAML/布局写入结果，保留未成功保存的修改状态，不误报全部成功。
- 切换文件、关闭编辑器或刷新前提示未保存的配置/布局修改，可取消或放弃。不自动存草稿；浏览器关闭提示尽力提供，崩溃无法恢复。

## 已确认：产品范围

- 首版只负责配置的新建、加载、编辑、校验和显式保存，不包含启动流程、运行监控或 BLOCK 处理，不修改正在运行的冻结定义。

## 页面与字段映射

### 页面结构

- 顶部：打开目录、文件列表、新建、保存、撤销/重做、只读 YAML 预览与校验状态。
- 配置区：公共配置、角色、Judge、主流程/子流程切换。
- 流程编辑区：节点添加入口、React Flow 画布、选中节点的属性面板。
- 错误区：展示现有校验链返回的字段路径/错误原因；能映射到节点或字段时定位，不用 toast 代替完整诊断。
- 角色、模型、persona 使用表单，不建成执行节点。长文本在属性面板编辑，不挤在画布节点中。

### 当前 v3 配置覆盖

| 配置位置 | 界面表达 |
| --- | --- |
| schemaVersion | 固定输出 agent-workflow/v3，不作为自由输入 |
| actorCommonPersona | 公共 persona 多行输入 |
| roles.<id> | 角色列表及 ID、persona、model、reuse、tools.deny 表单 |
| judgeRole | persona、model、tools.deny；不提供 reuse |
| model | provider、modelId、可选 reasoningEffort；不硬编码思考强度枚举 |
| workflow / childWorkflows.<id> | 主流程/子流程切换，各自编辑 startNode、returns、nodes |
| Actor execution | type、role、instruction |
| Actor checker | 当前支持的 judge.claim-correct 与可选共同 criteria |
| Actor results.<result> | 命名结果列表、criteria、target；每个结果对应一个输出端口 |
| Program execution | 内置 programId、可选 instruction/config；参数提示来自现有元数据 |
| Program results | 固定 PASS/FAIL，各自编辑必需的 criteria 与 target；不配置 Checker、不引入 Judge |
| Child execution | 本文件 childWorkflows 的引用 |
| Child onReturn | 根据被调用子流程的 returns 编辑返回映射，每项对应输出端口 |
| target.node / target.return | 同一流程内节点或已声明返回结果；互斥选择 |

工作流文件 ID 来自文件名，不另向 YAML 添加 name、description、ID 或 layout 字段。可选字段保留“未设置”与“已设置”的区别，不用空字符串替代缺省值。Program 参数允许按现有合同留待运行时提供，不擅自增加保存时必填要求。配置静态校验不等同于启动时模型可用性检查。

### 图与定义的对应关系

- 节点卡片只展示类型、ID、角色/程序/子流程引用和结果端口。
- 拖线更新对应结果的 target 或 Child 的 onReturn，不引入自由条件表达式。
- 一个出口对应一个目标；不同结果可以指向同一节点，边身份包含源节点及结果名，不能只用起点/终点作为唯一键。
- 主流程和各子流程分别显示画布。流程返回可显示为特殊目标标记，但不写成虚构的执行节点。
- 入口由 startNode 标记表达；主流程入口必须满足现有 Manager Actor 约束。
- 表单和画布使用同一份配置草稿，图数据为投影；节点坐标独立管理。重命名应同步更新相关引用；删除后不得静默改变业务路由，未完成修正时由校验阻止保存。

## 最小实施顺序（待整体审阅）

1. 客户端接入验证：正式面板/侧栏入口、共享 React、React Flow CSS 和最小 RPC，验证实际目录 API 可用性。
2. 文件闭环：授权目录、严格解析 YAML、自动关联布局、只读预览、同源配置校验和显式保存，先不扩展运行时。
3. 完整配置表单及图形映射：覆盖角色/模型/persona、三类节点、主流程/子流程和返回结果。
4. 编辑体验：基础撤销重做、简单初始摆放、自环限制、离开提醒、保存失败状态。
5. 验证与收口：运行现有验收入口，加最小配置往返和编辑器行为测试，浏览器验证后再申请部署。

## 验收重点

- 当前合法 v3 样例（不含编辑器明确拒绝的直接自环）加载、编辑、输出后重新解析，业务字段不丢失；覆盖可选 model/effort、persona、tools、reuse、Program 和 Child 映射。
- 直接自环导入明确拒绝，新建自环被阻止；多节点回路和不同结果汇入同一节点可编辑。
- 未授权/不支持目录 API/权限撤销时明确报错，不启动服务端路径读写替代机制。
- 无布局、布局损坏、节点新增/删除、同名节点属于不同子流程时按规则恢复。
- 只改位置不写 YAML；保存配置前复用当前校验；直接覆盖不检查并发修改；任一文件写入失败不误报成功。
- 撤销/重做覆盖语义修改和坐标修改；未保存时离开有提醒。
- 不新增运行控制入口，不触发 Run、不访问引擎状态库。
